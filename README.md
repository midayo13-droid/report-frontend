# report-frontend · 모아뷰티 일일 보고서 자동화 (화면)

휴대폰과 PC에서 쓰는 보고서 화면이에요. (Next.js 16 · Vercel에 올리는 것을 전제)
서버는 짝이 되는 저장소 **report-backend** 에 있어요. 화면만으로는 동작하지 않고, 서버 주소가 필요해요.

> 모든 회사, 사람, 숫자는 **과제용 가상 데이터**예요. 실제 개인정보, 결제, 의료 정보는 쓰지 않아요.

## ⚠ 첫 접속이 느릴 수 있어요

서버가 Render **무료 서버**라서, 한동안 접속이 없으면 잠들어요. 잠든 뒤 **첫 접속은 보통 1분 안팎** 걸려서, 로그인 화면이 늦게 뜨거나 시연 계정 목록이 나오지 않을 수 있어요. 잠시 기다린 뒤 **새로고침**하세요. (자세한 내용은 report-backend README)

## 확인용 계정

로그인 화면에서 **"시연용 계정으로 바로 들어가기"** 의 버튼을 누르면 **비밀번호 없이** 들어가요. (서버에서 `DEMO_MODE=true` 일 때)

### 관리자·일반(사용자) 계정 — 먼저 이것으로 확인하세요

| 역할 | 이름 | 이메일 | 할 수 있는 것 |
|---|---|---|---|
| **관리자** | 이서진 (이 이사) | `director@moabeauty.test` | 모든 보고서(승인 전 포함) 보기, **보고서 승인·반려**, **기준 수정안 승인**, 양식 설정, **시연 메뉴** |
| **일반(사용자)** | 송민호 (재고 담당) | `stock@moabeauty.test` | 보고서 조회, 비고 쓰기, 양식 설정·AI 도우미, 재고 기준 수정안 작성 |
| 일반(사용자) | 한유나 (마케팅 담당) | `mkt@moabeauty.test` | 같은 일반 권한, 광고 효율 기준 수정안 작성 |
| 일반(사용자) | 오세린 (운영 담당) | `ops1@moabeauty.test` | 같은 일반 권한 |
| 일반(사용자) | 문지훈 (운영 담당) | `ops2@moabeauty.test` | 같은 일반 권한 |

### 그 밖의 역할 계정

| 역할 | 이름 | 이메일 | 볼 수 있는 것 |
|---|---|---|---|
| 조회자 | 박대표 (대표) | `ceo@moabeauty.test` | **승인된 보고서만** 보기·PDF 내려받기 |
| 조회자 | 팀장 5명 | `lead.sales` · `lead.mkt` · `lead.ops` · `lead.stock` · `lead.admin` `@moabeauty.test` | 박대표와 같음 |
| 총관리자 | 오세린 (운영 담당 겸임) | `sysadmin@moabeauty.test` | 계정·권한, 연결 키, 이력 |

- 이메일과 비밀번호로 직접 로그인하는 칸도 있어요. 시연 계정의 비밀번호는 서버의 `DEMO_PASSWORD` 값이고, 정하지 않으면 기본값 `MoaDemo#2026` 이에요. (가상 계정 전용이에요.)
- 시연 계정은 서버가 처음 켜질 때 가상 데이터와 함께 만들어져요.

### 추천 확인 순서 (약 7분)
1. **이서진(관리자)** 으로 로그인 → 오늘 일일 보고서(승인 대기) 열기
2. 재고 표의 **AI 제안**, 비고 칸의 **AI 원인 후보 보기** 눌러 보기
3. **양식** 메뉴 → AI 양식 도우미에 "카테고리별 매출을 원그래프로 추가해줘" → 변경안 확인 → 적용
4. **승인** 메뉴 → 기준 수정안 승인 ("내일부터 적용돼요" 확인)
5. **시연** 메뉴(휴대폰은 더보기 안) → 일부러 수집 실패시켜 보기 → **수집** 메뉴에서 재시도 기록 확인
6. 보고서에서 **승인하고 공개하기** → 오른쪽 위 이름 → 로그아웃 → **박대표** 로 로그인해 승인된 보고서와 PDF 확인
7. 이서진으로 다시 로그인 → **시연** 메뉴 → **처음 상태로 되돌리기**

## 설정값 (환경변수)

| 이름 | 뜻 | 꼭 필요? | 예시 |
|---|---|---|---|
| `NEXT_PUBLIC_API_URL` | 서버(report-backend)의 API 주소 | **필수** | `https://report-backend.onrender.com/api` (끝에 `/api` 까지, `/` 로 끝내지 않기) |

- 이 값은 **비밀 값이 아니에요.** 화면 코드에 그대로 들어가서 브라우저에서 보여요. 그래서 DB 주소나 API 키는 이 저장소에 두지 않아요.
- `NEXT_PUBLIC_` 값은 **빌드할 때** 코드에 박혀요. 값을 바꾸면 **다시 배포(Redeploy)** 해야 적용돼요.

## Vercel에 올리기

1. Vercel에서 **Add New → Project** 를 고르고 이 저장소(`report-frontend`)를 가져와요 (Import).
2. 아래처럼 확인해요. (대부분 자동으로 맞춰져요)

| 칸 | 값 |
|---|---|
| Framework Preset | `Next.js` (자동) |
| Root Directory | `./` (그대로) |
| Build Command | `next build` (기본값) |
| Install Command | `npm install` (기본값) |
| Output Directory | 비워 둠 (기본값) |
| **Environment Variables** | `NEXT_PUBLIC_API_URL` = 서버 API 주소 |

3. **Deploy** 를 눌러요. 끝나면 `https://(프로젝트 이름).vercel.app` 주소가 생겨요.
4. 그 주소를 서버(Render)의 `FRONTEND_ORIGIN` 에 넣어요. (이걸 안 하면 브라우저가 서버 응답을 막아서 로그인이 안 돼요) 서버 설정을 바꾸면 서버가 다시 시작돼요.

## 내 컴퓨터에서 실행하기

서버(report-backend)가 먼저 켜져 있어야 해요. (기본 `http://localhost:4000`)

```bash
npm install
cp .env.example .env.local      # NEXT_PUBLIC_API_URL=http://localhost:4000/api
npm run dev                     # http://localhost:3000
```

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 개발용 실행 (코드를 고치면 바로 반영) |
| `npm run build` | 배포용으로 만들기 |
| `npm run start` | 만든 것을 실행 |

## 화면

로그인 · 보고서 목록 · 보고서 상세(그래프, 재고 AI 제안, 비고, PDF) · 승인 · 수집 상태 · 양식 설정(AI 도우미, 그래프 추가) · 기준 관리 · 이력 · 계정·연결 · 시연.
역할에 따라 보이는 메뉴가 달라요. 권한 규칙은 화면이 아니라 서버가 지켜요.
